# 单窗口，操作主屏、查看副屏

原生 macOS 工具，设备画面是主体。SwiftUI 系统字体用于操作和状态，等宽数字仅用于 display ID/尺寸。窗口背景和文字适配系统外观；所有设备画面共用黑色画布。键盘焦点以简短的中性文字提示，不用蓝色聚焦边框包围画面。

左侧约 210px，包含当前设备屏幕列表和录屏历史；右侧在一块黑色画布上按比例并排显示主屏和所有活跃副屏，屏幕间距为零，屏幕较多时横向滚动。工具栏提供设备选择、自动跟随新副屏、截图、录屏和齿轮设置菜单。主屏用于操作，副屏用于观察；不提供单屏布局切换。主屏提供点击、拖动、滚动、键盘与剪贴板控制，以及返回、主页和多任务入口。副屏和录屏回放不向设备发送输入。

活跃副屏自动加入列表和并排舞台。主屏键盘已聚焦时，新副屏不会改变选中屏幕、滚动位置或输入焦点；未聚焦时可自动跟随。副屏休眠、移除或断连后退出实时画布和设备列表；原先选中的活动副屏结束后选回主屏。副屏再次活跃时自动恢复。

侧栏历史展示已保存的录屏文件，每项包含时间和视频缩略图。点击后使用系统默认播放器播放。启动、保存录屏及切换保存目录后刷新；只读取当前录屏目录和本应用明确保存过的路径。手动保存位置在本机持久记录，不扫描其他目录。缩略图读取本地视频的前部画面，不自动播放，也不操作 Android 设备。

休眠或结束的源画面仍可留在内存中，用于当前录像里的状态和时间标注；侧栏不再提供副屏最后画面条目或清除这些条目的入口。PNG、MP4 和主动开启的诊断文件独立保存。

截图将当前画布中的主屏和所有活跃副屏合成为一张 PNG，包含滚动区域外的屏幕。导出画面紧贴排列，不带额外边距、间隙和标题栏；非实时画面的状态和时间直接叠在对应画面内。

手动录屏先选择保存位置，再将主屏和所有活跃副屏合成为无声 MP4，不依赖画布滚动位置或选中项。录制中新出现的活跃副屏自动加入；休眠、移除或断连的屏幕在本次录制中保留带状态和时间的最后画面。工具栏显示录制状态并提供停止入口。每次录制只保存一个完整视频，保存完成后可通过窗口底部的「查看录屏」在 Finder 中查看。切换设备或退出时完成并保存当前录制。

录屏高度最高 720 像素、宽度最高 2560 像素；12 fps、H.264，码率随输出面积调整，上限 1.6 Mbps。最终视频采用本次录制中最宽布局的比例，所有时刻按统一高度等比缩放、左侧对齐；画面间没有缝隙，上下不加多余区域。较窄的布局在右侧留空，因此新副屏尚未出现时，它后来的位置为空白。

屏幕新增、旋转等布局变化在内部写成临时片段，停止后合并为一个 MP4。合并期间显示正在保存，完成后历史中增加一个条目；没有布局变化时直接保存，无需重新编码。临时片段不进入历史；合并失败时保留片段，便于恢复。MP4 优先满足小体积的录制需求，暂不提供 GIF 或音频。

齿轮菜单提供「副屏开启时自动录制」，默认关闭并持久保存用户选择。开启后，当前设备出现活跃副屏且已有画面时开始，最后一个活跃副屏休眠、移除或断连时停止并保存；只结束其中一个副屏时继续录制。手动停止会抑制自动重启，直到所有副屏关闭；手动录制不会因副屏结束而停止。自动保存目录默认为 `~/Movies/Scrcpy Viewer`，支持选择目录和在 Finder 中打开。保存期间等待完成，再判断是否需要开始下一次录制。

断连、未授权、缺少依赖分别提供具体操作提示。静态页面没有新帧不等于休眠，使用系统源屏状态判断。主屏无论是否休眠都保留，供查看连接状态和主动唤醒。

屏幕发现基于 Android 系统接口，所有副屏使用一致的发现和只读观看规则。可用范围取决于设备的枚举与捕获权限。依赖准备使用本机 adb 和固定版本的官方 scrcpy 服务端；任何可选下载应明确展示来源和版本，并由用户主动发起。

设计复核：这是看设备的工作台，避免营销型大标题、装饰卡片和无关统计。只有屏幕列表、真实画面、连接状态和必要观看选项。
